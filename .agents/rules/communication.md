# 沟通、注释与文档

## 文档

- 给人看的用法写在 `README.md`：启动、目录、怎样加模块
- 给代理的约定写在 `AGENTS.md` 和 `.agents/rules/`
- 规则只保留必须遵守的约定，不把 `README.md` 整段抄进来
- 改了启动方式、目录职责或清单字段后，核对 `README.md` 是否还对

## 文档和代码不一致时

1. 先列出差异：文件路径、文档怎么写、代码怎么写
2. 先问用户：改代码对齐文档，还是改文档对齐代码
3. 用户确认后再动手
4. 不要擅自改代码去迁就可能过时的文档，也不要改文档去掩盖实现

## 用词

同一概念全程同一叫法。

| 中文 | 英文 / 代码 | 一句话 |
|------|-------------|--------|
| 工作台 | station | 整个站点；显示名来自清单的 `name` |
| 模块 | module | `modules` 里的一项，对应一个入口 |
| 清单 | `modules.json` | 模块注册表，导航只认它 |
| 外壳 | shell / `PAGE` | `serve.py` 里的整页：侧栏、顶栏、底栏、页头 |
| 页面片段 | page | `station/pages/<id>.html`，只含中间内容 |
| 分组 | group | 首页上的分组标题，可空 |
| 状态 | status | 非空时首页显示徽章；空表示这项可用 |
| 任务调度 | taskhub | 清单里的一个模块。派任务，员工经 `/api/v1` 领取 |
| 攒钱 | piggy | 清单里的一个模块。`/piggy/` 有外壳，`/piggy/app/` 没有 |

易混，先说清指的是哪一个：

- **页面片段 ≠ 整页**：片段里不要写 `html` / `head` / `body`；整页只有外壳
- **清单 ≠ 页面**：只改清单会出现入口；没有对应 html 时显示占位，不是 404
- **模块 id ≠ 显示名**：`id` 用于 URL 和文件名，`name` 给人看
- **外壳 ≠ 模块内容**：导航和版心在 `serve.py`，具体功能不写进外壳

## 与用户沟通

- 技术概念第一次出现时，用一句话说清它是干什么的
- 说「以谁为准」时写明两边分别是什么
- 给建议时说明原因和影响；不确定就问

## 写注释

- 只注释「为什么」和容易踩的坑，不复述代码在做什么
- 路径校验、片段为何不转义、清单字段缺省值，这类从代码本身看不出的约定要写清
- 注释用词与本文、`README.md` 一致
- 不要加无信息的文件头注释
