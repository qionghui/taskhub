# 验证约定

本仓库没有测试框架，也没有测试目录。不要假装已经跑过测试，也不要为了一次小改动引入测试依赖。

## 改了什么就验证什么

- 改 `serve.py` 的路由、清单解析、转义或资源路径：重新启动后实际请求
  - `/` 返回首页
  - 一个清单里存在的 `/<id>/` 返回该模块
  - 一个不存在的路径返回「没有这一页」
  - `/assets/` 不能用 `..` 读到 `web/assets/` 以外的文件
- 改 `station/modules.json` 或 `station/pages/`：不重启，刷新浏览器，看入口和中间内容
- 改工作计划的读写：重新启动后提交一条事项，刷新能看见；完成后未完成里没有，已完成里能查到
- 改 `station/learn.json`：不重启，刷新能看见。`/learn/?export=1` 的正文与这份文件一致。内容读不了时，页面要指出坏在哪一张
- 改小孩学习的管理：重新启动后，页面能导入一份合法内容，刷新后能看见，导出正文与文件一致。不合法的导入要指出坏在哪一张，且原文件还在。删掉一张后刷新，它和里面的卡片都没有了。宽屏和窄屏都能点到管理、删除、导入、导出，没有横向滚动
- 改任务调度：重新启动后 `GET /taskhub/` 能看见任务页。建一条任务并发布，员工预览和领取里有它，响应正文里没有 `plan_`。未推送就提交时要被拒绝。两台员工同时领同一条，只有一台成功。`/api/v1/` 以外的未知路径仍是「没有这一页」
- 改攒钱：重新启动后 `GET /piggy/` 带侧栏，中间是攒钱页面。`GET /piggy/app/` 是同一份页面，没有侧栏。`GET /piggy/api/data` 的目标和记录与 `station/piggy.json` 一致。记一笔后刷新，两边都能看见，文件里也有。乱提交要被拒绝，原文件还在。`/piggy/app/` 以外的未知路径仍是「没有这一页」
- 改 `web/assets/site.css`：宽屏（侧栏）和窄屏（顶栏 + 底栏）都要看。确认没有横向滚动，标题、卡片右缘和徽章没有被裁切或挡住

## 态度

- 修 bug 时先说明怎样复现，改完用同一步骤确认已经消失
- 检查具体结果：状态码、标题、名单是否出现、错误文案是否指出坏的是哪一项。不要只看「进程没退出」
- 清单损坏时应看到可读的错误页，而不是一份拼了一半的外壳
- 用户可见的界面改动，在浏览器里走一遍受影响的页面。只看代码不算验证完成
